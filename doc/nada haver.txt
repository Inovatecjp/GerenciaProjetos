Estrutura Genérica de Serviço no NestJS

Para criar um serviço genérico que pode ser reutilizado para diversas entidades, usaremos TypeScript generics. A ideia é que esse serviço possa realizar operações CRUD básicas que podem ser estendidas por serviços específicos.
Base Service

// src/common/base.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { Repository } from 'typeorm';

@Injectable()
export abstract class BaseService<T, ID> {
  constructor(protected readonly repository: Repository<T>) {}

  async findAll(): Promise<T[]> {
    return this.repository.find();
  }

  async findOne(id: ID): Promise<T> {
    const entity = await this.repository.findOne(id);
    if (!entity) {
      throw new NotFoundException(`Entity with id ${id} not found`);
    }
    return entity;
  }

  async create(entity: T): Promise<T> {
    return this.repository.save(entity);
  }

  async update(id: ID, entity: Partial<T>): Promise<T> {
    const found = await this.findOne(id);
    if (!found) {
      throw new NotFoundException(`Entity with id ${id} not found`);
    }
    return this.repository.save({ ...found, ...entity });
  }

  async remove(id: ID): Promise<void> {
    const result = await this.repository.delete(id);
    if (result.affected === 0) {
      throw new NotFoundException(`Entity with id ${id} not found`);
    }
  }
}

Estrutura Genérica de Controlador no NestJS

Da mesma forma, podemos criar um controlador genérico para manipular operações CRUD básicas. O controlador irá utilizar os métodos definidos no serviço genérico.
Base Controller

// src/common/base.controller.ts
import { Body, Delete, Get, Param, Post, Put, NotFoundException } from '@nestjs/common';
import { BaseService } from './base.service';

export abstract class BaseController<T, ID> {
  constructor(protected readonly service: BaseService<T, ID>) {}

  @Get()
  async getAll(): Promise<T[]> {
    return this.service.findAll();
  }

  @Get(':id')
  async getOne(@Param('id') id: ID): Promise<T> {
    return this.service.findOne(id);
  }

  @Post()
  async create(@Body() entity: T): Promise<T> {
    return this.service.create(entity);
  }

  @Put(':id')
  async update(@Param('id') id: ID, @Body() entity: Partial<T>): Promise<T> {
    return this.service.update(id, entity);
  }

  @Delete(':id')
  async remove(@Param('id') id: ID): Promise<void> {
    await this.service.remove(id);
  }
}

No código findOne(@Param('id') id: string), o sinal de + antes de id na chamada this.itemsService.findOne(+id); é usado para converter a string id para um número. Em JavaScript e TypeScript, colocar um + antes de uma variável é uma maneira rápida e comum de converter valores que são recebidos como strings para números. Este é especialmente o caso em ambientes web, onde parâmetros de rotas, como IDs em URLs, são tipicamente recebidos como strings.

Esse tipo de conversão é necessário porque muitas operações de banco de dados ou lógicas internas dependem de comparações de tipo estrito ou operações matemáticas, que requerem valores numéricos reais em vez de strings. Portanto, ao acessar uma rota como /items/123, o 123 seria inicialmente tratado como uma string. O uso de +id assegura que ele seja tratado como um número quando passado para a função findOne, que provavelmente espera um número como argumento para buscar o item correspondente no banco de dados ou em uma coleção.

Aqui está um resumo de como isso funciona:

    @Param('id') id: string: Captura o parâmetro id da URL como uma string.
    +id: Converte essa string para um número.

Essa abordagem é simples e eficaz, mas deve ser usada com cuidado, pois converter strings que não representam números (como "abc") resultará em NaN (Not a Number), o que pode levar a comportamentos inesperados ou erros na aplicação. Em tais casos, é aconselhável adicionar verificações adicionais ou validações para garantir que a conversão é segura e que o valor convertido é válido.

// src/common/base/base.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { Repository } from 'typeorm';

@Injectable()
export abstract class BaseService<T extends BaseEntity, ID> {
  constructor(protected readonly repository: Repository<T>) {}

  async findAll(): Promise<T[]> {
    return this.repository.find();
  }

  async findOne(id: ID): Promise<T> {
    const entity = await this.repository.findOne(id as any);
    if (!entity) {
      throw new NotFoundException(`Entity with id ${id} not found`);
    }
    return entity;
  }

  async create(entity: T): Promise<T> {
    return this.repository.save(entity);
  }

  async update(id: ID, entity: Partial<T>): Promise<T> {
    await this.findOne(id); // Ensures entity exists
    return this.repository.save({ ...entity, id } as any);
  }

  async remove(id: ID): Promise<void> {
    const result = await this.repository.delete(id as any);
    if (result.affected === 0) {
      throw new NotFoundException(`Entity with id ${id} not found`);
    }
  }
}

O TypeORM utiliza arquivos de declaração de tipo para TypeScript. Esses tipos algumas vezes precisam ser instalados separadamente. Para instalar os tipos do TypeORM, execute:

npm install @types/typeorm --save-dev

No entanto, vale notar que, em muitos casos, o TypeORM já inclui seus próprios arquivos de declaração de tipos diretamente no pacote, então esse passo pode não ser necessário. Se o erro persistir mesmo após a instalação do @types/typeorm, pode ser um indicativo de que há outras questões em jogo.
3. Verifique o tsconfig.json

Assegure-se de que seu tsconfig.json está configurado para incluir os diretórios corretos onde os módulos estão instalados. O TypeScript usa este arquivo para determinar quais arquivos incluir em sua compilação e onde procurar tipos. Certifique-se de que as opções moduleResolution e baseUrl estão configuradas corretamente:

{
  "compilerOptions": {
    "moduleResolution": "node",
    "baseUrl": "./", // Ou ajuste conforme a estrutura do seu projeto
    "paths": {
      "*": ["node_modules/*", "src/types/*"] // Ajuste conforme necessário
    }
  }
}

4. Reinstale os pacotes

Problemas com o node_modules ou com o cache do npm podem algumas vezes causar esse erro. Tente limpar o cache do npm e reinstalar todos os pacotes:

rm -rf node_modules/
rm package-lock.json // ou yarn.lock se você estiver usando Yarn
npm cache clean --force
npm install

5. Verifique as Importações

Certifique-se de que as importações estão corretas em seus arquivos TypeScript. Por exemplo, uma importação correta do TypeORM seria:

import { Entity, PrimaryGeneratedColumn } from 'typeorm';

Verifique se não há erros de digitação ou importações incorretas que possam estar causando o problema.
6. Reinicie seu Editor de Código

Em algumas situações, o ambiente de desenvolvimento pode não atualizar seu estado baseado nas mudanças feitas no node_modules ou no tsconfig.json. Fechar e reabrir seu editor de código ou IDE pode ajudar a recarregar as configurações e resolver problemas de resolução de módulos.

Se após seguir estas etapas o problema persistir, pode ser útil verificar a documentação do TypeORM ou buscar por questões específicas similares no GitHub ou Stack Overflow.
